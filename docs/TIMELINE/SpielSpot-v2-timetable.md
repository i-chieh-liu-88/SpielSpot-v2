## 部署計畫已納入

沿用已討論的 **Render（Express API）＋MongoDB Atlas（資料庫）＋Clerk（登入）**。這次只更新工作計畫，不代表已部署或通過檢查。

| 日期 | 部署工作 | 完成時留下的證據 |
| --- | --- | --- |
| 10/1–10/2 | 確认方案、帳號、backend 依賴與 Render 指令 | 設定清單、可重現的安裝方式 |
| 10/7–10/8 | Atlas、secrets、安全、啟動與健康檢查 | 測試紀錄、部署前檢查結果 |
| 10/9 | Render 首次部署與 Atlas 寫入驗證 | HTTPS URL、部署 commit、資料寫入證據 |
| 10/12 | 自動部署、proxy、冷啟動與完整流程 | 新部署紀錄、重新部署後資料仍存在 |
| 10/13–10/14 | 部署手冊、乾淨安裝、資料匯出與恢復步驟 | README、操作紀錄、可回復版本 |

**依 SpielSpot v2 調整通用教學：**

- 使用 Mongoose，不安排 Prisma migration；沿用 Clerk，不新增教學中的自建 `JWT_SECRET`。Cookie 與自建登入路由的檢查僅在實際使用時適用。
- Render Root Directory 和指令須配合 repo 的依賴位置，先於 10/2 確認，不直接照抄單一目錄專案範例。
- Atlas 網路規則優先使用 Render 服務提供的 outbound IP ranges，不把允許所有 IP 當成預設。CORS 是瀏覽器來源規則，不能取代身分與權限驗證。
- proxy 設定依實際流量路徑驗證；索引先檢查差異與必要性，不把可能刪除索引的 `syncIndexes()` 當成每次部署必跑的指令。
- 免費額度、休眠、備份能力與帳單條件在 10/1 查核，不將教學內的價格或限制視為已確認現況。

來源：[部署藍圖](https://github.com/i-chieh-liu-88/Backend-Deployment/blob/main/deployment-blueprint.md)、[部署前檢查清單](https://github.com/i-chieh-liu-88/Backend-Deployment/blob/main/pre-deployment-checklist.md)、[平台比較與概念](https://github.com/i-chieh-liu-88/Backend-Deployment/blob/main/README.md)。網路設定參考 [Render 官方 Atlas 連線說明](https://render.com/docs/connect-to-mongodb-atlas)。

## 如何使用

- 每天只看當天區塊，依順序完成 **3 項任務**；完成後將 `[ ]` 改成 `[x]`。
- 每項時間包含查資料、操作與記錄；一般為 **60＋60＋60 分鐘**。
- **10/7**為 **45＋60＋75 分鐘**；**10/9**為 **45＋90＋45 分鐘**，每天仍是 3 小時。
- 「當日目標」是預期成果，不代表已完成。若任務已驗證，將時間用於補強或修正。

## 卡住時怎麼調整？

1. **先記錄**：卡在哪裡、已試過什麼、下一步要做什麼。
2. **調整下一個工作日**：替換較低優先的工作，不把任務自動加到週末。
3. **保留必要項目**：核心 API、安全、測試、部署與文件優先；額外功能延後。

部署準備已取代部分重複盤點時間，不額外增加工時。若 10/9 尚未上線，10/12 優先排除部署問題，再調整文件與展示練習；不跳過必要安全檢查，也不自動占用週末。

此計畫延續現有 Express、MongoDB、Clerk 後端。前端串接以展示核心流程為主，不包含新動畫、圖片上傳等額外功能。
